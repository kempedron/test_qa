# Баги API студентов (http://194.87.126.16)

Проверял методы GET/POST/PUT/DELETE на студентах. API странно себя ведёт: почти всегда возвращает HTTP 200, а об ошибке сообщает только полем `"status": 0` в теле. Ниже то, что точно сломано.

## 1. GET /student/{id} не находит только что созданного студента
Создаёшь через POST, берёшь `id` из ответа, сразу же делаешь GET на этот же id — приходит `{"message":"Student not found","status":0}`. Студента как будто нет, хотя только что создали.

## 2. PUT /student/{id} не обновляет
Даже для существующего студента PUT возвращает `{"message":"Student not found, student not updated","status":0}`. Данные не меняются.

## 3. DELETE /student/{id} не удаляет
DELETE отвечает `{"message":"Student deleted successfully","status":1}`, но если потом сделать GET по тому же id — студент всё ещё на месте и отдаёт свои данные.

## 4. DELETE несуществующего студента возвращает успех
DELETE /student/999999 (или любого другого выдуманного id) возвращает `200 {"message":"Student deleted successfully","status":1}`. Хотя студента нет, API говорит, что удалил.

## 5. GET несуществующего студента — 200 вместо 404
GET /student/999999 возвращает HTTP 200 с телом `{"message":"Student not found","status":0}`. Должно быть 404.

## 6. POST с неверными данными — тоже 200
Если отправить POST без обязательных полей или с левым `gender` (например, `"other"`), приходит `200` с текстом вроде `"Wrong JSON, student not created"` или `"Wrong gender, student not created"`. Ожидался бы 400.

## Итог
API не follows простых правил HTTP: ошибки клиента маскируются под 200 OK, а реальные операции (обновление, удаление, поиск по id) не работают, хотя ответ говорит об успехе.
